The v3 Maintenance dialog has "Delete" ("Delete this maintenance record?"), but there's no DELETE /maintenance_visits/:id; the routes only have index, new, show, create, update and cancel. Please add a delete, or confirm the UI should drop it. Delete is hidden in the app for now.

Force End Trip has no call. The v3 trip drawer, on a run that's on the road, has More > Force End Trip. scheduler.md § 5.2 and the routes have no way to end or complete a run. Please add one (e.g. PATCH /occurrences/:id/end), or confirm the UI should drop it.

School route notices have no route list. POST /notices takes audience: "school", school_id and route_ids, but nothing documents how to list a school's routes for route_ids. Is it the routes of the adopted plans in GET /schools/:id/plans? Please document which ids and how to list them.

Rate limit (429) uses a different error format. After about 10 /portal/session* calls from one IP in a few minutes, the API returns {"error":"Too many requests"} with no Retry-After header, set in config/initializers/rack_attack.rb. Every other error is { error: { code, message } }. Please use the usual error object and add Retry-After. Lookups also count towards the limit, so a few mistyped emails lock the sign-in screen.

The Client Portal has no data endpoints. Only the Portal session exists (clients.md § 7). v3 has Home, Bookings, Approvals, Trips, Map, Notices, Invoices, Users, Approval Flow and Settings. The Portal pages run on sample data until these exist.

Save Time on a one-off trip only moves the run. PATCH /occurrences/:id/time { scope: "from_here" } on a one-off trip returns 422 "Only a recurring trip has later runs" (app/services/occurrences/edit.rb:71). The app sends scope: "today" instead, so the run gets shift_minutes and shows "Moved +20 min". In v3, Save Time moves the trip itself. Should a one-off trip's new time be a run shift, or a change to the trip's start time?
